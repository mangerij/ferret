FunctorNeumannBC

Imposes the integrated boundary condition , where is a functor.

Description

FunctorNeumannBC is a generalization of ADNeumannBC which is used for imposing flux boundary conditions on systems of partial differential equations (PDEs) where the flux is represented by a spatially- and temporally-varying MOOSE Function. That is, for a PDE of the form where is the domain, and is its boundary, a FunctorNeumannBC object can be used to impose the third condition if the function is well-defined for all relevant times and . In this case, the parameters "functor" and "coefficient" are functors, whose product represents the mathematical function (or if "flux_is_inward" is set to false), and the user must define one or more sidesets corresponding to the boundary subset via the "boundary" parameter.

    C++ Type:std::vector<BoundaryName>

    Controllable:No

    Description:The list of boundary IDs from the mesh where this object applies

  • functorThe functor to impose. A functor is any of the following: a variable, a functor material property, a function, a postprocessor or a number.

    C++ Type:MooseFunctorName

    Unit:(no unit assumed)

    Controllable:No

    Description:The functor to impose. A functor is any of the following: a variable, a functor material property, a function, a postprocessor or a number.

    C++ Type:NonlinearVariableName

    Unit:(no unit assumed)

    Controllable:No

    Description:The name of the variable that this residual object operates on

  • search_methodnearest_node_connected_sidesChoice of search algorithm. All options begin by finding the nearest node in the primary boundary to a query point in the secondary boundary. In the default nearest_node_connected_sides algorithm, primary boundary elements are searched iff that nearest node is one of their nodes. This is fast to determine via a pregenerated node-to-elem map and is robust on conforming meshes. In the optional all_proximate_sides algorithm, primary boundary elements are searched iff they touch that nearest node, even if they are not topologically connected to it. This is more CPU-intensive but is necessary for robustness on any boundary surfaces which has disconnections (such as Flex IGA meshes) or non-conformity (such as hanging nodes in adaptively h-refined meshes).

    Default:nearest_node_connected_sides

    C++ Type:MooseEnum

    Options:nearest_node_connected_sides, all_proximate_sides
